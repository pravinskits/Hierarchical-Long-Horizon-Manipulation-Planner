# Demonstration Guide

This guide explains how to present a polished 3-5 minute demonstration of the complete system, from goal generation to adaptive recovery and metric evaluation.

## Prerequisites
1. Open terminal 1 and start the API:
   ```bash
   python -m uvicorn src.hlmp.api.server:app --reload
   ```
2. Launch the Android Application via Android Studio (or run `scripts/end_to_end_demo.py` if no emulator is available).

## Presentation Workflow

### 1. Project Introduction (00:00)
- Explain the research goal: preventing cascading error propagation in long-horizon manipulation tasks by integrating structured hierarchical planning with adaptive recovery.
- Open the Android Dashboard to show backend connectivity and system health.

### 2. Natural-Language Task Creation (00:30)
- Navigate to the **Create Task** screen.
- Enter the goal: *"Move the red cube to the target, then move the blue cube beside it."*
- Click **Create Task**.
- Explain that the backend is translating the abstract text into verified architectural steps.

### 3. Hierarchical Plan Review (01:00)
- The app automatically navigates to the **Plan** screen.
- Show the chronological list of Subgoals (e.g., `Pick`, `Move`, `Place`).
- Highlight that these steps are strictly validated against the skill registry to prevent LLM hallucinations.

### 4. Start Simulation and Execution (01:30)
- Click **Execute Plan**.
- Transition to the **Task Execution** polling screen. 
- Point out the active progress bar and subgoal status updates tracking real-time PyBullet telemetry.

### 5. Controlled Failure Injection (02:00)
- The system is hardcoded (in the demo/benchmark configs) to inject a **CONTROLLED EXPERIMENTAL FAILURE** at a specific step (e.g., dropping the blue cube).
- Emphasize to the audience that this is an explicitly labeled injection to test the recovery loop, not a random system crash.

### 6. Failure Detection & Classification (02:20)
- Show the UI state update to indicate a failure occurred. 
- Explain how the `FailureDetector` read PyBullet constraints and the `FailureClassifier` mapped it to a structured enum (e.g., `GRASP_FAILURE`).

### 7. Adaptive Recovery (02:40)
- The Execution screen should show the system retry/re-grasp the object.
- Navigate to the **Recovery History** tab.
- Explain the logic: the Recovery Manager escalated from a simple retry to a full re-grasp strategy, which successfully resolved the issue without aborting the entire 10-step plan.

### 8. Task Completion & Metrics (03:30)
- Wait for the progress bar to hit 100%.
- Navigate to the **Experiments Benchmark** screen to show how this single run aggregates into the broader data.
- Conclude by showing the CSV and Matplotlib outputs generated by `scripts/quick_benchmark.py` that prove full adaptive recovery significantly mitigates error propagation at horizons > 10.
